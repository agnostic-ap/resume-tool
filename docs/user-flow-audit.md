# 用户路径审计

日期：2026-05-21

目标：把自己代入真实用户，而不是只做代码检查，找出“下一步不知道去哪”“入口承诺和落地不一致”“跨端状态不可信”的地方。

## 用户 1：正在制作简历的求职者

### 首次进入

现在应用打开后有完整的示例数据，看起来很饱满，这是优点。但它也掩盖了真实空白状态。用户新建空白简历后会直接进入编辑器，缺少一个明确的“先填什么、再填什么”的路径。完整度卡片会给泛化建议，但具体字段没有顺序引导。

修复方向：
- 首次进入提供三种选择：空白创建、导入备份、使用示例。
- 空白简历进入编辑器后显示引导清单：个人信息、个人简介、最近经历、技能、导出检查。
- 空白章节卡片要有明确主操作，不要靠示例数据撑起完整感。

### 从工作台到编辑器

工作台里的“AI 定制”按钮会进入编辑器。进入编辑器后，用户看到的 AI 编辑助手只是本地生成一段建议，然后追加到个人简介。更完整的 JD 定制能力其实已经写在 `WorkspacePanel.vue` 里，包括 `generateJdDraft`、章节前后对比、采纳所选章节、从草稿创建投递记录，但整块 UI 被 `v-if="false"` 隐藏了。

用户感受：我点的是 AI 定制，但实际得到的是文本建议，不是基于 JD 的简历生成。

修复方向：
- 把真正的 JD 定制流程移动到编辑器右侧或编辑器抽屉。
- 复用 `backendApi.generateAssistantResumeDraft`。
- 对个人简介、工作经历、技能、项目展示结构化前后对比。
- 支持从草稿直接创建关联的投递记录。

### 内容编辑

编辑器的 form/source/diff 隐喻是有辨识度的，但还有几个预期不一致点：
- AI 显示开关会隐藏分数和导出建议，但不会隐藏编辑器里的 AI 助手。
- AI 助手文案说可以输入目标岗位/JD，但输出并没有调用后端 JD 匹配。
- 简历选择器里包含已归档简历，容易让“归档”变成无意中继续编辑。
- 模板选择既有独立页面，也在编辑器右侧出现。这个可以保留，但编辑器里应该是主路径，因为用户需要立刻看预览变化。

修复方向：
- `showAI` 对所有 AI 相关卡片一致生效。
- 已归档简历设为只读，或从编辑器活跃选择中排除，除非用户显式恢复。
- 模板页保留完整浏览，编辑器右侧作为主要切换入口。

### 风格调整

现在“网站风格”和“简历风格”的概念已经比之前清晰：
- 网站风格在设置页。
- 简历风格在编辑器右侧。

剩余不顺：
- 设置页没有实时展示应用主题会如何变化。
- 简历风格虽然有 mini preview，但还需要更明确地告诉用户：这里影响预览和 PDF；设置页不影响导出简历。

修复方向：
- 设置页增加应用界面预览卡片。
- 编辑器风格卡保留简历/PDF 预览。
- 重复使用明确标签：“仅影响网站界面”“影响简历和 PDF”。

### 导出

预览里有页数和分页线，但导出仍然会直接执行。用户可能导出一个分页错乱或内容溢出的 PDF，却没有被阻止或被建议如何修。

修复方向：
- 增加导出前检查。
- 检测联系方式过长、章节跨页、内容溢出、必要章节为空等问题。
- 给出快捷修复：紧凑密度、减小字号、隐藏低价值章节、继续导出。

## 用户 2：管理投递进度的求职者

### 收藏一个岗位

投递管线的表单基础不错，已有公司、岗位、阶段、JD 归档、跟进日期、联系人、备注等字段。

不顺的地方：
- 表格仍然是主要心智模型。跟踪多个岗位时，用户更期待看板、步骤条或详情抽屉。
- 进度备注不能单独设置事件日期或事件阶段。
- 已有进度事件不能编辑或删除。
- 跟进日期有数据，但没有形成明显的待办队列。

修复方向：
- 增加岗位详情抽屉。
- 增加可编辑时间线事件：日期、阶段、标题、备注。
- 增加过期跟进高亮和“今日待跟进”视图。
- 增加按阶段分组的看板：待投递、已投递、初筛、面试、Offer、关闭。

### 从 AI 草稿到投递记录

隐藏的 JD 流程可以创建带 tailoring metadata 的投递记录，这个方向是对的，但它没有接入可见的编辑器 AI 流程。

修复方向：
- “根据 JD 生成草稿”同时产出简历 diff 和可选投递记录。
- 投递详情里展示这条记录来自哪份简历草稿、哪个 request id、匹配分和命中关键词。

## 用户 3：记录职业成长经历的人

现在成长记录页被包装成“双周更新”，但本质是一个会重置的清单。用户点“我已更新”后，备注会被清空。这样产品丢掉了后续 AI 生成简历最需要的职业记忆。

用户感受：我记录了东西，但历史去哪了？

修复方向：
- 增加 append-only 的成长经历条目。
- 字段包括：日期、类型、公司/项目、内容、量化指标、技能、证据链接、隐私标记。
- AI 定制简历时可以选择引用哪些成长条目。
- 展示“尚未用于任何简历”“已用于某份简历/某次投递”的状态。

## 用户 4：超管

管理端使用 Ant Design，方向表达是对的，但目前还是静态控制台：
- 用户、角色、简历、投递、API 请求都是写死数组。
- 左侧菜单不能切换真实页面。
- “同步主仓库配置”“管理密钥”“查看全部”“打开审计日志”等按钮没有实际动作。
- 没有登录、权限校验、危险操作二次确认。

作为平台所有者的感受：这是一个控制台样子，但还没有控制权。

修复方向：
- 增加真实管理端路由和后端管理接口。
- 接入 `/api/v1/platform/requests` 平台调用日志。
- 增加 API Key 管理、审计日志、部署健康、配置同步状态、用户/工作区归属。
- 超管数据必须先登录并通过角色校验后才能访问。

## 用户 5：接入我们平台能力的外部系统

后端已经有平台草稿接口和请求记录，但集成体验还不完整：
- 没有 OpenAPI 文档。
- 没有 curl 示例或 SDK 示例。
- API 鉴权还是单个环境变量密钥，不是按 client 分配的 scoped key。
- 前台/管理端看不到请求耗时、失败原因、生成文档 id、幂等命中等细节。

修复方向：
- 发布 `/api/v1/resume-drafts` 的 OpenAPI 文档。
- 增加后端 schema 与前台/管理端消费者之间的契约测试。
- 增加 per-client API Key、scope、quota、rate limit 和请求详情页。

## 横向信任问题

### 保存状态

顶部 `Saved` 只监听 `store.data`。它不反映简历元数据、投递记录、设置、导入、后端同步失败或重试状态。

修复方向：
- 在 store 中增加同步队列状态。
- 区分本地已保存、云端同步中、云端失败、离线本地模式。
- 失败操作要可见，并提供重试。

### 本地化

简历内容可以按设计不跟随语言切换，但产品 UI 仍有硬编码文本，比如 `LIVE`、`Tw`、`preview.pdf`、`content.mdx` 和部分进度标题。管理端目前也基本是中文单语。

修复方向：
- C 端所有产品界面文案进入 locale 层。
- 管理端明确是中文超管专用，或补同一套语言层。

### 架构

`WorkspacePanel.vue` 现在承担了太多路由级页面：工作台首页、简历列表、模板、成长、投递、隐藏 AI/JD、历史、设置，以及大量业务逻辑。

修复方向：
- 拆成路由级组件。
- 抽出 JD 定制、简历库、投递管线、成长记录 composable。
- 在继续扩功能前给这些路径补组件测试。

## 建议执行顺序

1. 把真实 JD 定制恢复到编辑器。
2. 把成长记录改成持久职业记忆。
3. 增加投递详情抽屉和可编辑进度时间线。
4. 让保存、同步、导出状态真实可信。
5. 管理端接入真实后端日志和认证。
6. 为平台 API 增加 OpenAPI 与契约测试。
7. 拆分 `WorkspacePanel.vue` 的路由级页面和业务逻辑。
