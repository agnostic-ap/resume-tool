# UX Rubric

这份 rubric 用来判断 AI 每轮该修什么，以及修完是否真的改善了用户体验。

## 评分方式

每个发现按 0-2 分评估：

- 0：缺失、误导、不可用或用户容易犯错。
- 1：基本可用，但状态不清、路径绕、反馈弱或需要猜。
- 2：清晰、可信、可恢复，用户知道下一步和后果。

优先修“关键路径上 0 分或 1 分的问题”，不要只追求视觉润色。

## 发现必须包含

每个 UX 问题都要写清楚：

- 用户是谁。
- 用户正在完成什么任务。
- 当前看到什么或做了什么。
- 为什么这会让用户困惑、失败或不信任。
- 最小可执行修复是什么。
- 怎么验收它真的好了。

## 核心维度

### 1. 入口和方向感

用户进入页面后是否知道：

- 当前页面是做什么的。
- 主要动作是什么。
- 下一步应该去哪。
- 空白状态下该如何开始。
- 从工作台进入编辑器后，上一个 CTA 的承诺是否延续。

P0 信号：点击一个强 CTA 后，落地页面没有对应能力。

### 2. 闭环完成度

关键路径是否能从开始走到结果：

- 空白简历能否完成核心字段并导出。
- JD 定制能否从输入 JD 到采纳草稿，再到创建投递记录。
- 投递能否从保存岗位推进到面试、Offer 或关闭。
- 成长记录能否沉淀并被后续简历复用。

P0 信号：路径中间断掉，用户只能手动绕路。

### 3. 信任和可恢复性

用户是否能相信系统状态：

- 保存、同步、离线、失败是否区分清楚。
- 导出前是否提醒明显问题。
- 失败是否有原因和重试。
- 破坏性动作是否确认，必要时是否可撤销。
- 导入是否预览后再覆盖。

P0 信号：显示 Saved，但真实数据可能没有保存成功。

### 4. AI 预期管理

AI 入口是否诚实、可控、可追踪：

- 文案是否准确描述真实能力。
- 是否有输入、生成中、失败、重试、结果、采纳、撤销。
- 用户是否知道 AI 改了哪里，为什么改。
- 采纳后是否能追踪来源 request id 或 JD 快照。
- 关闭 AI 后是否所有 AI 相关 UI 一致隐藏。

P0 信号：按钮承诺 JD 定制，结果只追加本地建议。

### 5. 信息架构和效率

用户是否能快速找到对象和动作：

- 简历、投递、成长记录是否可搜索、筛选、排序。
- 已归档对象是否避免误编辑。
- 命令面板是否能打开真实业务对象。
- 表格、详情、看板、时间线是否匹配任务心智。

### 6. 状态覆盖

每个重要区域至少要考虑：

- 空状态。
- 加载中。
- 成功。
- 失败。
- 部分成功。
- 离线或后端不可用。
- 权限不足。
- 长文本或大量数据。

### 7. 响应式和可访问性

前端改动要检查：

- 390px 左右窄屏是否有不可读、重叠、按钮挤爆。
- 1280px 桌面是否密度合理。
- 按钮有清楚 label 或 aria-label。
- 表单错误和状态不只依赖颜色。
- 键盘和焦点路径没有明显断点。

### 8. 文案质量

文案应该具体、可信、少废话：

- 写“根据 JD 生成章节草稿”，不要写“AI 智能赋能简历”。
- 写“云端同步失败，可重试”，不要写“发生错误”。
- 写“导入前预览 3 份简历和 5 条投递记录”，不要直接覆盖。

## 优先级定义

- P0：关键路径断点、数据可信问题、危险动作、明显承诺不一致。
- P1：高频体验摩擦、对象管理效率、信息架构、可恢复性不足。
- P2：增强型质量、视觉回归、平台化、架构拆分、长期维护性。

## Done 的定义

一个 UX 改进完成时，必须能回答：

- 哪个用户场景变好了。
- 用户现在能多完成什么。
- 哪个状态或失败路径被覆盖了。
- 用什么测试、构建或截图验证过。
- 是否还有剩余风险或下一步切片。
