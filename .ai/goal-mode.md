# Codex Goal Mode Operating Loop

这是 Resume Tool 的长期 AI 维护主入口。Goal 模式每次启动时都按这个流程工作。

## 0. Goal 的边界

推荐目标是“完成 1 个体验改进闭环”，而不是“永久完善产品”。一个闭环必须包括：

1. 恢复上下文。
2. 选择一个可本轮完成的问题。
3. 复现或确认当前体验。
4. 修改代码或文档。
5. 运行合适的验证。
6. 更新维护记忆。
7. 给出清晰交接。

如果用户明确要求多个闭环，完成一个后再选择下一个，不要把多个主题混在同一次改动里。

## 1. 恢复上下文

开始后先读取：

- `.ai/README.md`
- `.ai/product-memory.md`
- `.ai/ux-rubric.md`
- `.ai/backlog.md`
- `.ai/qa-scenarios.md`
- `.ai/session-log.md`
- `TODO.md`
- `PRD.md`
- `docs/user-flow-audit.md`

然后运行或查看：

- `git status --short`
- `rg --files`
- 相关子项目的 `package.json`

如果工作区已有用户改动，先读受影响文件，判断是否会影响本轮目标。不能回滚用户改动。

## 2. 选择本轮问题

优先选择满足这些条件的问题：

- 对真实求职者、平台运营者或外部开发者有明显体验价值。
- 能在本轮独立完成并验收。
- 有明确入口、失败态或验收标准。
- 不需要大范围重构也能先前进一步。
- 不会和当前用户未完成改动冲突。

优先级顺序：

1. P0 关键路径断点：首次使用、JD 定制、保存同步、导出、投递生命周期。
2. 信任问题：状态不真实、失败不可恢复、危险操作无确认。
3. 高摩擦但小范围的问题：空状态、文案误导、入口不一致、移动端重叠。
4. 架构拆分和平台化任务，只有在已有测试或明确边界时再做。

本轮目标必须写成一句用户价值，例如：

```text
让用户从工作台点击“AI 定制”后，能在编辑器里看到真实 JD 输入和草稿生成入口，而不是只看到本地文本建议。
```

## 3. 建立基线

在改代码前确认当前行为：

- 读相关组件、store、API 和测试。
- 如果是前端交互，启动本地服务并用浏览器走一遍关键路径。
- 如果是后端或数据模型，读 schema、store、测试和 API 调用方。
- 记录最小复现场景，后续写进 `.ai/session-log.md`。

不要只凭 TODO 判断，必须看当前代码。

## 4. 实现约束

- 改动要小，尽量贴近现有组件和 store 模式。
- 不做无关重构、换框架、换设计系统。
- 前端应保持产品工具气质：清晰、密度合理、状态可信，不做营销页式装饰。
- UI 文案要像真实产品，不写“AI 魔法”“智能赋能”这类空泛承诺。
- 所有 AI 入口都要明确真实能力、失败态和关闭策略。
- 破坏性动作要有确认；能撤销的地方尽量给撤销。
- 复杂逻辑尽量补测试；高风险共享行为必须补测试。

## 5. 验证矩阵

按改动范围选择验证，不要求每轮全跑，但必须说明选择理由。

前端 C 端：

```bash
cd code/front
npm run test
npm run build
```

后端：

```bash
cd code/backend
npm run test
npm run typecheck
```

管理端：

```bash
cd code/admin
npm run typecheck
npm run build
```

跨端或配置：

```bash
node scripts/check-workspace.mjs
node scripts/sync-config.mjs
```

前端体验改动还需要浏览器验收：

- 桌面视口：至少 1280 x 800。
- 窄屏视口：至少 390 x 844，或明确说明当前项目不支持该路径。
- 检查空状态、加载态、失败态、按钮文案、文本溢出、遮挡和主要路径是否能走完。

## 6. 更新维护记忆

每轮结束前必须更新：

- `.ai/backlog.md`：对应事项状态、完成说明、剩余切片或新发现的问题。
- `.ai/session-log.md`：追加一条最新日志，包含目标、文件、验证、风险和下一步建议。

如果发现新的体验问题，但本轮不修，写入 backlog，必须包含：

- 用户场景
- 证据
- 影响
- 建议切片
- 验收标准

## 7. 完成标准

只有同时满足以下条件，才算完成本轮 Goal：

- 本轮选定问题已经实现或被明确证伪。
- 合适的测试、构建或手动验收已完成。
- 维护文件已更新。
- 最终回复说明改了什么、验证了什么、还有什么风险。

如果同一个外部阻塞连续出现，且没有可安全推进的替代切片，再向用户说明阻塞点。
